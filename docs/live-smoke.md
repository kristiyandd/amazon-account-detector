# Manual test guide

Every behaviour the automated tests cannot reach with a real Amazon session is checked here by
hand: before a release, and by anyone who wants to see the extension work. Each test lists what to
do and what you should see. Mark it ✅ or ❌. If it fails, write down what you saw instead.

The texts in quotes are the exact popup texts, or their beginning where they end in "…". Times and
ages will differ from the examples.

## Before you start

**You need:**

- Chrome 120 or newer, and the extension loaded unpacked from `dist/` or the release zip
  ([README, Install](../README.md#install)). Pin its toolbar icon so the badge is visible.
- **Account A:** an Amazon account you can sign in to on amazon.com.
- **Account B:** a second amazon.com account, needed only for test 14 (wrong account). With
  one account, run the one-account version of test 14 below the table instead.
- Optional: an account on amazon.de (or .co.uk, .it, .fr) for test 5.
- For tests 6–7: a Chrome profile that has never visited amazon.co.uk or amazon.fr (a new
  profile works). Otherwise the popup shows a real answer at once; mark tests 6–7 as skipped.

**Useful tools:**

- **Open the popup:** click the extension icon in the Chrome toolbar.
- **Open the service-worker console:** go to `chrome://extensions`, find Amazon Account
  Detector, and click the **service worker** link next to "Inspect views". A DevTools window
  opens. Type the commands from the tests on its **Console** tab.
- **Start clean:** in that console run
  `chrome.storage.local.clear(); chrome.storage.session.clear()`, then close and reopen the
  popup. This forgets every result, the expected accounts and the cooldowns. It does not sign
  you out of Amazon.
- **Optional, detailed log:** `chrome.storage.local.set({ debug: true })` in the same console
  prints every step of a check ([debugging.md](debugging.md)).

Run the tests in order. Tests 1–12 need only account A.

**Test 14 with only one account:** after test 13, close the popup and run this in the
service-worker console. It makes the extension expect a made-up address, so your real account
becomes the wrong one:

```js
crypto.subtle
  .digest("SHA-256", new TextEncoder().encode("other.person@example.com"))
  .then(async (digest) => {
    const hash = [...new Uint8Array(digest)].map((b) => b.toString(16).padStart(2, "0")).join("");
    const { expected } = await chrome.storage.local.get("expected");
    expected.byMarketplace.us = { hash, hint: "o•••n@e•••.com" };
    await chrome.storage.local.set({ expected });
  });
```

You should see: the badge turns into a red **!** at once, without opening the popup. The popup
shows "Wrong account", "Signed in as …, but Amazon.com should use o•••n@e•••.com." and **Expect
this account instead**; pressing it removes the alert and the badge turns green again. This
version does not test the automatic re-check after a real account switch.

If the stored result was signed in, the pill is an orange **Last known** instead of the green **Signed in**; if it was signed out, the grey **Not signed in** pill stays. Command for test 20 (makes the stored US result two days old):

```js
chrome.storage.session.get("accounts", ({ accounts }) => {
  accounts.byMarketplace.us.checkedAt = Date.now() - 2 * 24 * 3600 * 1000;
  chrome.storage.session.set({ accounts });
});
```

## After testing

Start clean (above) if you used a shared profile, and turn the debug log off with
`chrome.storage.local.remove('debug')`.
